## 3. 圆环捕手：已确认的核心玩法语义（不可擅自改写）

圆环捕手是一个**顶部开口的圆环形挡板**。用户已多次澄清：圆环必须是圆的，不是 U 型；顶部有缺口，缺口两端逐渐收尖，端部厚度更薄。

### 3.1 几何与缺口

- 圆环是圆形环体，顶部有开口。
- 缺口是瞄准/进出通道，不是实体几何墙。
- 缺口两端的刀锋逐渐收尖；端部更薄，减少控制逻辑必须考虑的厚度。
- 缺口宽度和圆环直径是瞄准系统的两个不同尺度。
- 缺口通行宽度要扣除球半径和安全余量，不能只检查球心。
- 如果球体直径大于缺口有效净空，则不应判定为可穿过；交由外环壁接球/攻击逻辑处理。
- 缺口的逻辑区域与瞄准系统挂钩，但不能创造一堵“缺口墙”。

### 3.2 球的出生与可见外观

- 球的起始点仍然在圆环**内部底部**，不是缺口。
- 发球后球从内腔向上运动，通过顶部缺口离开/进入。
- 圆环关卡中，表情包代替普通球的可见外观；**隐藏的是普通球的绘制，不是物理球**。
- 真实球体的坐标、速度、半径、碰撞检测、轨迹都必须保留。
- 表情中心必须与真实球心对齐。
- 表情背景尽可能透明；不可出现黑色边框或黑色底块，但图标本身必须有足够对比度，不能因为透明处理而完全看不见。
- 表情状态：
  - 😂 得分/成功（按实际事件定义）
  - 🤪 飞行中
  - 😣 落空
- “落空”不是简单地撞墙。需定义为从目标附近擦过且未命中，短暂显示约 0.5 秒（可通过实测调整），随后恢复飞行表情。
- 球掉出屏幕/失去生命可以正常处理，但重生后回到原来的内腔底部发球点。
- 表情绘制与物理判定严格分离，不能让表情状态影响碰撞。

### 3.3 两种瞄准/决策模型

圆环捕手的瞄准系统有两种决策模型：

1. **缺口直径/净空模型（捕捉、进出、控球）**
   - 当球的尺寸可通过缺口时，球可以经过缺口进出内环壁。
   - 配合内环壁操作规则，能够捕捉球、减速球、移动球和控制球。
2. **圆环直径/外壁模型（攻击、反弹、增能）**
   - 瞄准宽度由球直径决定并与缺口净空区分。
   - 当球无法安全通过缺口，外环壁可以接住球，执行攻击、加速、改变路径。
   - 不可把这两套判定合并成一个简单的“瞄准宽度”。

### 3.4 内软外硬（最核心的物理设计）

- **内环壁：软。** 用于捕捉、减速、导流、控球；保留一定切向运动，降低法向反弹。可以利用不完美的内环壁轮廓打破球在左右方向高速震荡的平衡。
- **外环壁：硬。** 用于反弹、攻击、加速、改变路径。
- 用户曾经考虑过内环凸点，后来明确决定**删除凸点**，改为不完美/非完全对称的内环壁形状。不能重新加回凸点。
- 任何减速都不能让球速度归零或造成永久停滞；减速必须设置安全下限/回退。
- 外壁加速必须有速度上限和单次增益上限。
- 真实碰撞一律由游戏的生产物理函数处理；动画不能假装球被接住或发射。

## 4. 圆环捕手的智能控制目标

用户希望圆环捕手不再“笨”：它要知道球速快慢、接下来会撞哪里、什么时候捕捉、什么时候减速、何时加速、如何甩球、如何移动球，并且能组合基础技能。

目标系统架构：

```
RingSensor      只读感知：球况、几何、缺口、碰撞 ETA、威胁
    ↓
RingState       状态分类：生存 / 捕捉 / 增能 / 攻击 / 过口
    ↓
RingPlanner     规划：选择接触区、动作窗口、技能组合
    ↓
RingSkills      执行：捕捉、减速、加速、甩球、移动球、过口
    ↓
RingPhysics     生产碰撞物理：内软外硬、连续碰撞
    ↓
RingEvaluator   评估：技能是否成功、球速变化、漏接、攻击收益
    ↺
RingTuning      有界参数调优：只调策略参数，不自动改物理常数
```

### 4.1 RingSensor（只读）

感知输出至少包括：

- 球的位置、速度向量、速度大小、速度倍率、速度分类。
- 速度趋势/加速度（平滑后）。
- 球相对圆心的距离、极角、内外壁净距。
- 下一次内壁/外壁接触预测与 ETA。
- 缺口有效净空、预计通过时间、横向偏移、是否可通过。
- 球的方向、预测可信度、威胁等级。
- 焦点球 ID/引用变化检测。

速度分类历史上有 crawl / slow / cruise / fast / extreme 等层级；具体阈值应读取当前生产代码，不要凭手册硬编码。

要求：
- 传感器只读，不得写球的位置、速度、半径。
- 不得消耗游戏共用随机数。
- 输入 NaN、Infinity、非法半径时返回 invalid，清理历史速度趋势和 ETA，不得把污染数据送入状态机。
- 缺省速度可以兼容为静止观测（需遵循当前生产实现与测试）。
- ETA 是近似感知，不得冒充完整轨迹仿真。
- 多球换焦时必须清空旧焦点的速度历史，不能把不同球的速度变化混在一起。

### 4.2 RingState（状态机）

至少考虑这些状态/意图：

- SAFE_CATCH：接球风险迫近，放弃攻击和技能，优先接球。
- CAPTURE：高速球或危险球用内环软壁接住、卸力。
- BOOST：低速、能量不足时利用外壁受控增能。
- AIM_ATTACK：速度/轨迹稳定且有可信目标时组织攻击。
- GUIDE_GAP：缺口净空充分、方向可行时引导球通过。
- RECOVER：传感器无效、预测冲突、换焦、模式变化、暂停/待发球等情况下清理技能并回到安全状态。

状态切换要有滞回，避免阈值附近抖动；但高优先级的接球危险可以打破滞回。

### 4.3 RingPlanner（规划与仲裁）

优先级固定：

1. 生存/安全接球。
2. 防卡壁、防停滞、防过速。
3. 控球与缺口引导。
4. 进攻准备（加速/甩球）。
5. 攻击收益。

规划请求应具备 accepted/action/reason/confidence/expiresAt 等可解释信息（具体以当前代码结构为准）。

Planner 只输出意图和挡板目标，不直接写球物理状态。

### 4.4 RingSkills（基础技能）

每项技能必须有：触发条件、目标、时间窗口、超时、冷却、取消原因、失败回退和评估结果。

**A. 捕捉/减速（CAPTURE）**
- 高速球优先考虑内环软壁。
- 内环接触后降低法向能量、保留部分切向运动。
- 不得减速到零；若出现停滞风险，取消进一步耗散。
- 低速球不要盲目继续减速。

**B. 外壁加速（BOOST）**
- 低速球/持续减速时，在安全可达的情况下选择外壁。
- 外壁真实碰撞产生受控加速和路径变化。
- 必须有目标速度上限、单次增益上限和冷却/防重复触发。
- 高速球不应继续盲目增能。

**C. 甩球（SLING）——用户定义，不能改成普通弹反**
这是一个独立的连续动作链：

1. 内环接球：Auto 主球真实碰到内环软壁，先进入可控状态。
2. 左右震荡：圆环挡板在内环控制球左右往返震荡；一次完整左右往返为一个周期。震荡次数越少，甩出速度越慢；次数越多，甩出速度越高。
3. 单向短冲：震荡结束后，圆环向选定方向短距离冲刺。
4. 反向缺口端释放：短冲方向的反侧内环缺口刀锋端真实接触球后，利用该端甩出球。
5. 甩出角度由短冲距离决定；短冲距离越长，出射角度按映射变化。
6. 震荡次数控制速度，短冲距离控制角度，两个控制量解耦。
7. 释放必须发生在生产碰撞事件中；不能把缺口变成实体墙、不能传送球心、不能仅靠动画或计时器伪造释放。
8. 未真实碰到目标刀锋端时超时取消，不得强制发射。
9. Auto 关闭、焦点球变化、切换挡板类型、暂停、游戏状态变化等应安全取消/清理技能。
10. 生存风险升级时可以中断甩球。

**D. 移动球/导流（GUIDE）**
- 通过内环切向作用与圆环平移改变球的位置/轨迹。
- 限制最大导流时间、位移和摆动次数。
- 避免左右高速震荡陷阱；需要不完美内环形状、合理耗散和动作决策配合。
- 导流不是瞬移球。

**E. 缺口引导（GAP_GUIDE）**
- 只有球体几何净空为正且预测方向可行时才能通过。
- 净空不足/擦边风险时取消，外壁接管。
- 缺口仍然是通道，不是实体碰撞体。

### 4.5 技能组合

允许的组合示例（以当前实现为准，继续完善）：

- 蓄力甩球：CAPTURE → GUIDE → SLING → AIM_ATTACK。
- 高速卸力：CAPTURE → GUIDE_GAP 或安全回中 → AIM_ATTACK。
- 反向甩球：选择接触侧 → 挡板横移 → SLING。
- 连续增能：BOOST → 速度上限检查 → AIM_ATTACK。
- 控球等待：CAPTURE → GUIDE → 等待高置信度攻击窗口。
- 任一阶段风险升级：立即取消组合，转 SAFE_CATCH。

每个阶段必须由真实事件/状态推进，不能仅靠无条件时间递增。必须支持超时、目标失效、焦点切换、关卡变化、暂停、待发球、Auto 关闭等中断。

### 4.6 RingEvaluator / RingTuning

有界记录：
- 技能请求、接受、完成、取消次数和原因。
- 技能执行前后速度/速度倍率。
- 内外壁接触次数与类型。
- 接球成功率、漏接次数、有效攻击命中率。
- 平均控球时长、无效横移、预测误差、低置信度回退。
- 统计数组必须有长度上限。
- 调优只允许修改明确列出的策略阈值、权重和冷却参数。
- 不允许在线学习自动改内外壁物理系数。
