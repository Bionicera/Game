# 统一物理引擎：物理宪法与最小接口草案（P1）

> 状态：设计草案 v0.1，待解析测试与生产 A/B 验证。  
> 依据：`docs/PHYSICS_P0_AUDIT.md` 的静态审计；不代表生产代码已迁移。  
> 设计目标：先建立适合 Portrait Breakout 的二维最小物理内核，不引入不必要的通用引擎复杂度。

## 1. 物理宪法

1. **唯一状态所有者**：纳入 PhysicsWorld 的对象，其位置、速度只能由 PhysicsWorld/明确的初始化与规则效果接口改变；策略层不得旁路写入。
2. **几何与响应分离**：Collider 只回答接触几何；Solver 只根据 Contact、材质和质量/表面速度求解；规则层处理得分、耐久、生命、掉落和关卡。
3. **先相对运动，再求冲量**：碰撞必须使用接触点双方的表面速度差，而不是只看球的绝对速度。
4. **驱动边界不假装静止**：挡板和圆环初期作为运动学刚体；其速度参与相对速度，外部驱动所做的功单独记账。
5. **规则效果必须显式**：发球、减速道具、诅咒重力、外环游戏增益等通过命名接口进入，不伪装成自然碰撞。
6. **不变量可测**：静止无摩擦墙不应凭空增加动能；分离接触不重复施加冲量；恢复系数与摩擦边界满足定义；运动边界能量变化与冲量/表面速度相符。
7. **生产迁移可回滚**：旧路径保留为基线，按对象类别逐步切换，任何阶段均可退回稳定版本。

## 2. 单位与坐标

| 量 | 约定 |
|---|---|
| 长度 | CSS px |
| 时间 | 秒 |
| 速度 | px/s |
| 加速度 | px/s² |
| 质量 | 游戏质量单位（无量纲标定值，需实验选定） |
| 冲量 | mass·px/s |
| 力 | mass·px/s² |
| 坐标 | x 向右、y 向下 |
| 角度 | 弧度；初期只用于几何，不启用刚体自转 |

质量不必对应现实公斤，但必须为正、可比较且在冲量方程中一致使用。初期可将球质量归一化为 1；运动学/静态边界逆质量为 0。未来若引入动态砖块或旋转刚体，再扩展惯量与角速度，不在第一版预埋复杂系统。

## 3. 刚体类型与状态

### 3.1 DynamicBody
- `id`、`type`
- `position=(x,y)`、`velocity=(vx,vy)`
- `force=(fx,fy)`（每步清零）
- `mass>0`、`invMass=1/mass`
- `enabled`、`sleeping`（初期可不实现睡眠）

### 3.2 KinematicBody
- 具有位置、几何、线速度及接触表面速度。
- 由控制器/动画驱动，不受碰撞冲量改变自身速度。
- `invMass=0`；其速度仍参与接触相对速度和驱动做功账本。
- 第一批对象：普通挡板、月牙/半圆/三角挡板、圆环。

### 3.3 StaticCollider
- 几何固定，表面速度为零，`invMass=0`。
- 第一批对象：屏幕边界、堡垒固定墙、普通静态砖块、弹力柱。
- 砖块被击中后的耐久/销毁属于 Game Rules，不改变接触求解职责。

### 3.4 非刚体规则实体
落砖、俯冲敌机、蛇头火箭、粒子等先不强制塞进刚体求解器。P1 只要求它们声明运动模型、时间步和碰撞规则归属；是否迁移由后续性能与玩法证据决定。

## 4. 几何与接触契约

### 4.1 Collider
最小支持：
- Circle
- AxisAlignedBox
- Segment / plane
- ParametricCurve（圆环内壁、外壁弧段与缺口边缘）

几何模块只输出候选接触，不修改 Body 速度，不调用得分/砖块逻辑。

### 4.2 Contact
建议最小字段：
- `bodyA`、`bodyB`（或静态边界 ID）
- `point`：世界坐标接触点
- `normal`：单位法线，方向固定为 **从 B 指向 A**
- `penetration`：非负穿透深度；分离/间隙接触不生成求解冲量
- `toi`：连续碰撞时间比例（若采用扫掠检测）
- `surfaceVelocityA/B`：接触点表面速度
- `featureId`：几何特征标识，便于去重和日志
- `materialA/B`

法线方向必须统一。任何窄相位实现若无法稳定确定法线，必须显式返回无效/退化状态，不能默默使用零向量。

## 5. 接触求解方程

令相对接触速度：
`u = (vA_contact - vB_contact)`，法线 `n` 从 B 指向 A。

法向速度：
`un = dot(u,n)`。

只有 `un < 0`（双方沿法线方向正在接近）才施加法向冲量。对无旋转、仅平移的第一版：
`jN = -(1+e) * un / (invMassA + invMassB)`。

冲量作用：
- A：`vA += jN * invMassA * n`
- B：`vB -= jN * invMassB * n`

运动学/静态边界 invMass 为 0，因此不会被冲量改变；球会获得相应速度响应。

切线 `t=(-n.y,n.x)`，切向相对速度 `ut=dot(u,t)`。第一版采用库仑上限：
`jT = clamp(-ut / (invMassA+invMassB), -mu*jN, +mu*jN)`。
再沿 t 对双方施加相反冲量。若摩擦模型在生产 A/B 中造成明显玩法偏差，先比较无摩擦切向保持与受限摩擦模型，不私自更改材质参数。

恢复系数 `e` 与摩擦系数 `mu` 必须来自 Material 配置并限制在合法范围；不同材质不能在碰撞函数中散落硬编码。

## 6. 接触分离与连续碰撞

- 速度冲量与位置穿透修正是两件事，分别记录。
- 位置修正只消除真实穿透，不允许把缺口补成墙。
- 使用小比例、带阈值的穿透修正，避免反复抖动；参数由解析测试确定。
- 高速球与薄墙/曲线使用 sweep/TOI，不能只靠帧末重叠检测。
- 同一时间步多接触需要稳定排序、去重与有限迭代；第一版先明确当前游戏是否需要多接触迭代，再以角点/同时接触测试决定复杂度。

## 7. PhysicsWorld 的时间步职责

当前生产循环为帧 dt 上限 0.033 秒，再按球速自适应子步；尚无统一固定步累积器。

P1 候选方案：
- PhysicsWorld 对外提供 `step(dt)`。
- 首选实验候选固定步长 1/120 秒；每帧最多追赶 4 步，超额时间显式记录为 dropped/capped time，不静默吞掉。
- 每个固定步内对高速对象使用 sweep/TOI；不以无限增加子步代替连续碰撞。
- 若第一关 A/B 或性能测试证明 1/120 不合适，再对照 1/90、1/180，不凭感觉定案。
- 规则计时器与渲染仍可使用帧 dt；物理世界只接受受控时间步。暂停/隐藏/横屏期间不推进物理时间。

以上是待验证方案，不在 P1 文档阶段直接替换生产 loop。

## 8. 物理事件与规则事件

物理层输出：
- `ContactBegin` / `ContactResolved`
- 接触点、法线、相对速度、冲量、碰撞前后速度
- 动能变化、运动学边界做功估计、穿透修正量
- 数值异常（非有限值、退化法线、超限速度、迭代耗尽）

规则层订阅物理事件后执行：
- `BrickDamaged`、`BrickDestroyed`、`ScoreAwarded`
- `LifeLost`、`ExtraBallSpawned`、`LevelCleared`
- 技能阶段变化与表现反馈

规则层可以发出明确的外部效果请求（如重力、减速、发球初始速度），但请求必须标注来源、持续时间和作用对象，并由物理世界在步进边界统一应用；不允许任意代码直接写 `vx/vy`。

## 9. 诊断与验收用例

1. 球撞静止无摩擦平墙：法向速度反号并按 e 缩放，切向速度保持；无额外能量来源。
2. 球撞运动学挡板：相对速度决定冲量；挡板不被反冲，但记录驱动器做功。
3. 分离中的球与墙：不施加重复冲量。
4. 零距离/退化法线：安全返回并记录异常，不产生 NaN。
5. 球撞圆角/曲线：法线与接触点连续，扫掠不穿透。
6. 球撞砖块：先解接触，再由规则层扣耐久/得分；砖块死亡不反向污染求解器。
7. 圆环顶部缺口：缺口不生成 Contact；刀锋端几何按真实曲线/端点定义。
8. 内环软材质：通过 e/mu/阻尼模型表达耗散，不直接把球速夹到经验目标值。
9. 外环增能：先确认是材质恢复还是明确的游戏效果；不能把 1.045 倍速度乘法伪装为自然弹性。
10. 真实第一关：固定种子配对 A/B + 新种子泛化，完整通关率为最终判断。

## 10. 尚待决策（不隐藏不确定性）

- 球的质量归一化为 1 是否足够，额外球是否同质量。
- 第一版是否启用切向摩擦，或先只做法向冲量并保留切向速度。
- 圆环曲线端点/刀锋端的接触法线定义与缺口净空契约。
- 固定步长与每帧追赶上限的最终选择。
- 弹力柱 1.035 倍增益、圆环外壁增益和内壁速度下限应成为材质参数还是显式规则效果。
- 普通砖块是否始终静态，特殊关卡移动砖/敌机是否仅作为运动学边界。
- 多接触迭代次数及 CCD 的最小覆盖范围。

这些问题进入 P2 前必须通过解析场景或生产测量给出决策，不允许在迁移时临时拍脑袋。
