## 设计总目标

把圆环捕手从「只会预测落点、选择内壁或外壁」升级为具备感知、状态判断、控球技能、技能组合与经验优化能力的控制系统。

核心原则：

1. **球的物理真实状态是唯一事实来源。** 表情只是外观；感知层读取真实位置、速度、半径与碰撞几何。
2. **感知与物理分离。** 传感器只读，不直接改变球速、位置、碰撞或随机数序列。
3. **决策与执行分离。** 决策层选择技能，技能层提出动作，物理层按明确规则执行。
4. **生存优先于攻击。** 先保证可接球，再考虑控球与得分。
5. **每次只引入可验证的小改动。** 不同时重写碰撞、瞄准和自动驾驶。
6. **其他四种挡板不受影响。** 圆环专属代码必须受 `shape === 'ring'` 约束。
7. **不以静态代码检查冒充手机实测。** 每个阶段分别记录语法/逻辑检查和用户设备验证。

## 圆环捕手的物理语义（不可随意改写）

- 顶部缺口是逻辑瞄准与进出通道，不是实体墙，也不是球的出生点。
- 球的待发位置仍在圆环内腔底部；发球后从内腔向上穿过缺口。
- 内环壁是软捕捉面：降低法向反弹、保留大部分切向运动，帮助减速和导流。
- 外环壁是硬攻击面：反弹并适度加速，可改变球路。
- 圆环整体移动、接触位置与接触法线可参与甩球和路径控制。
- 缺口通行判断必须扣除球半径与安全余量；球不能通过时应由外壁策略接管。
- 圆环模式下表情包替代球的可见外观，但真实球体及碰撞半径始终存在。

## 完整系统施工图（目标架构）

本项目按「先可靠控球，再追求攻击收益」施工。最终结构如下：

```
RingSensor      只读感知：球况、几何、缺口、碰撞 ETA、威胁
    ↓
RingState       状态分类：生存 / 捕捉 / 增能 / 攻击 / 过口
    ↓
RingPlanner     规划：选择目标接触区、动作窗口、技能组合
    ↓
RingSkills      执行：捕捉、减速、加速、甩球、移动球
    ↓
RingPhysics     现有真实碰撞：内软外硬、连续碰撞检测
    ↓
RingEvaluator   评估：动作是否成功、球速变化、漏接、攻击收益
    ↺
RingTuning      有界参数调优：只调策略权重，不直接改物理常数
```

**硬性架构边界**
- Sensor 不得写入球体位置、速度、半径，不得消耗游戏共用随机数。
- State / Planner 只能输出意图与目标，不得直接改球体物理量。
- Skills 只能通过明确的动作接口提出控制请求；真实碰撞仍由 RingPhysics 处理。
- 任何技能必须具备前置条件、执行窗口、最大持续时间、冷却、取消条件和失败回退。
- 接球安全优先级永远高于攻击收益；临近漏接时必须放弃甩球与进攻。
- 不增加会让球停滞、卡壁或无限增速的机制；所有增益/耗散均须有界。
- 多球时先锁定焦点球，再为焦点球规划动作；焦点改变时清理旧球状态。
- 非 Ring 模式不运行 RingSkills / RingPlanner，不改变现有四种挡板。
- 本轮及后续只提交开发代码与测试，不配置 Pages、不发布游戏。

## 传感器规格与验证范围

| 传感器 | 当前 / 目标输出 | 必测边界 |
|---|---|---|
| 速度 | 绝对速度、基准倍率、crawl/slow/cruise/fast/extreme | 0、阈值两侧、极高速 |
| 趋势 | 平滑加速度、accelerating/stable/decelerating | 速度突变、噪声、换焦 |
| 方向 | vx/vy、运动角 | 四象限、近垂直、近水平 |
| 空间 | 圆心距离、极角、内外壁净距 | 中心、内壁、壁带、外壁外 |
| 缺口 | 预计过口时间、预测横向偏移、净空 | 正中、擦边、不可通过、向下运动 |
| 碰撞预测 | 内外壁 ETA、下一壁面 | 靠近/远离/切向掠过 |
| 能量 | 速度倍率平方代理值 | 速度翻倍时能量代理约四倍 |
| 目标 | 可攻击砖块、路径收益 | 无目标、单目标、多段连击 |

传感器的 ETA 是近似预测，不得冒充完整轨迹仿真；规划器必须允许「未知 / 低置信度」并回退到安全接球。

## RingState 状态机规格

状态不只由速度决定，还必须结合方向、碰撞窗口、缺口通行和球的生存风险。

| 状态 | 进入条件（初版） | 主意图 | 退出 / 保护 |
|---|---|---|---|
| SAFE_CATCH | 预计漏接或接触窗口极近 | 放弃攻击，优先接球 | 风险解除后重新规划 |
| CAPTURE | 高速、极高速或常速持续加速 | 内壁软捕捉 / 卸力 | 速度下降且安全窗口打开 |
| BOOST | 低速、能量不足或持续减速 | 外壁增能 | 达到速度目标或风险上升 |
| AIM_ATTACK | 常速稳定且有可信目标 | 外壁出射与攻击 | 目标失效或风险上升 |
| GUIDE_GAP | 球即将通过且缺口净空足够 | 对准逻辑通道 | 通过缺口或通行条件失效 |
| RECOVER | 传感器无效、预测冲突或多球换焦 | 中心安全策略 | 传感器重新稳定 |

RingState 已与 RingPlanner / RingSkills 分离。SAFE_CATCH 由底部接球 ETA 触发；RECOVER 在传感器失效、Auto 关闭、暂停、待发球及焦点失效时清理技能/组合状态。高风险接球可中断正在执行的甩球。

## 基础技能规格（RingSkills）

每个规划请求统一提供 `accepted`、`action`、`reason`、`confidence` 与 `expiresAt`；只提交挡板目标/技能意图，不由 Planner 直接写球体物理。真实速度变化由 RingPhysics 的碰撞响应完成。

1. **捕捉 / 减速（CAPTURE）**
   - 条件：高速或极高速、内壁接触窗口可信。
   - 动作：优先内壁接触；保留当前软法向反弹与切向耗散。
   - 安全：速度不得低于可持续运动下限；若出现停滞风险则取消继续耗散。
2. **外壁加速（BOOST）**
   - 条件：低速、外壁接触可预测、攻击/生存风险可接受。
   - 动作：利用现有硬壁反射与受控增益。
   - 安全：设置目标速度上限与单次增益上限；达到上限不再追求加速。
3. **甩球（SLING）**
   - 条件：Auto 主球在圆环模式下真实接触内环软壁；目标方向可确定。
   - 阶段 A · 内环捕捉：内壁软响应先接住球，记录焦点球与甩球方向。
   - 阶段 B · 左右震荡：圆环挡板交替横移；一次完整左右往返计为一个震荡周期。低速球允许更多周期，高速球减少周期。
   - 阶段 C · 单向短冲：震荡完成后，圆环沿选定方向短距离冲刺；冲刺距离由目标方向/偏移确定。
   - 阶段 D · 反侧缺口端释放：只在球真实接触短冲反侧的内环刀锋端点时释放；缺口仍是通道，不增加虚构碰撞墙，不瞬移球心。
   - 速度映射：完整震荡周期数决定甩出速度；周期越多，甩出越快。
   - 角度映射：短冲距离决定甩出角度；短冲越长，出射角越宽，与震荡次数解耦。
   - 安全：Auto 关闭、焦点球变化、非圆环模式或释放端点超时均取消；出射速度有界，接球优先级仍可中止技能。
4. **移动球（GUIDE）**
   - 条件：球在内环可控区域、轨迹预测可信。
   - 动作：利用内壁切向导流与圆环平移，让球移动到目标角区。
   - 安全：设置最大导流时长、最大位移和振荡检测。
5. **通过缺口（GAP_GUIDE）**
   - 条件：球体几何净空为正，预测横向误差在通道内。
   - 动作：控制圆环相对位置，使球沿逻辑通道进出；缺口始终不是实体碰撞墙。
   - 安全：净空不足立即取消，不把「擦边」判为可通过。

## RingPlanner 技能组合与仲裁

**决策优先级固定为：**
1. 生存与安全接球（SAFE_CATCH）
2. 防止卡壁、停滞、过速（RECOVER / 能量保护）
3. 控球与缺口引导（CAPTURE / GUIDE / GAP_GUIDE）
4. 进攻准备（BOOST / SLING）
5. 攻击收益（AIM_ATTACK）

**组合脚本**
- 蓄力甩球：CAPTURE → GUIDE → SLING → AIM_ATTACK。
- 高速卸力：CAPTURE → GUIDE_GAP 或安全回中 → AIM_ATTACK。
- 反向甩球：选择接触侧 → 挡板横移 → SLING。
- 连续增能：BOOST → 速度上限检查 → AIM_ATTACK；达到上限禁止再次增能。
- 控球等待：CAPTURE → GUIDE → 等待高置信度攻击窗口。
- 任一阶段风险升级：取消组合并回退 SAFE_CATCH。

组合必须支持超时、目标失效、焦点球变化、关卡状态变化和暂停/待发球时中断。

## RingEvaluator 与可解释调优

记录只保留必要的短期统计，不写入个人数据、不联网：
- 技能请求 / 接受 / 取消次数与原因。
- 技能执行前后速度、速度倍率、内外壁接触类型。
- 接球成功率、漏接次数、有效攻击命中率、平均控球时长。
- 无效横移、策略反复切换、预测误差与低置信度回退次数。

调优只允许修改明确列出的策略阈值、权重和冷却参数；物理系数（内壁软反弹、切向耗散、外壁增益）必须独立评审，不由在线学习自动修改。统计必须有上限，不能无限增长。

### C. 物理场景测试
- 内壁法向速度下降、切向保留且整体耗能。
- 外壁反射方向正确且速度增益有限。
- 球穿过缺口时不触发虚构碰撞。
- 球从内腔底部发射，落点与可视表情位置一致。
- 高速球内壁捕捉、低速球外壁攻击、甩球、移动球。
- 高速连续碰撞、贴壁、极端入射角、屏幕边缘和大 dt。

### D. 自动驾驶 / 回归
- Auto 开/关、暂停/恢复、待发球、掉命、重开、换关。
- 多球焦点切换、目标砖块被其他球先打掉。
- 其他四种挡板的基线行为与绘制。
- 音乐、HUD、toast、表情系统、特殊关卡不回归。
- 随机种子固定时测试可复现；表情随机不得改变物理随机序列。

### E. 设备兼容（最后由用户手机实测）
- 竖屏/横屏、触控拖动、屏幕安全区、全屏、音频自动播放限制。

## 本轮集中审查记录

### 已发现并修复
- **角度区间跨界：** `Math.atan2` 输出 `[-π, π]`，内环轮廓使用从缺口一侧开始的连续角区间。传感器在左下半区原先直接把负角传给轮廓函数，会错误读取局部壁厚；现已将角度映射到轮廓连续区间。
- **滞回意图冲突：** 策略模式被滞回保留时，旧版仍可能写入新状态的技能意图，出现 `mode=capture` 却 `intent=boost`。现已在滞回期保持模式与意图一致；缺口引导可独立覆盖，临近壁面高优先级风险可打破滞回。
- **多球切换：** 传感器在焦点球变化时重置旧球加速度趋势，防止速度历史串扰。

### 2026-11-19 · 设计里程碑 · 从第一代缺口宽度瞄准转向生存域完全体瞄准
- 用户与开发侧共同明确：圆环捕手的核心目标不是单纯扩大缺口瞄准命中率，而是让球尽可能始终处于可持续控制、可恢复并最终可通关的物理状态集合。正式将下一代方向命名为「生存域完全体瞄准系统」（Viability-Domain Aiming）。
- 第一代缺口宽度瞄准系统：主要围绕缺口宽度、球体半径与瞄准偏移判断能否穿过通道；它解决的是局部几何可通行性，不足以表达碰撞后的长期生存与通关结果。
- 新一代系统的核心概念：生存域不是单纯的二维位置热图，而是包含球的真实位置/角度、飞行方向、速度、内外壁接触几何、挡板位置与速度、缺口净空及后续可行控制的状态空间。最终目标是识别「从该状态出发，是否存在可行控制序列使球持续生存并完成关卡」。
- 已明确的两类失败机制必须分开建模：
  1. **内环壁：速度处理能力边界。** 用户指出内环全部实体范围在几何上均可用于接球；约 20% 的观察失败率来自左右甩球后的初始飞行速度超过圆环捕手的处理速度，导致捕捉失败。这里不应按内环角度建立黑名单，而应测量不同入射方向/挡板状态下的最大可靠接球速度，并建立速度安全边界。约 80%/20% 是用户当前观察与待验证假设，不是已测得的统计结论。
  2. **外环壁：碰撞位置与反射结果风险。** 用户指出外环横轴以上区域约有 80% 可生存机会；直接命中左右横轴接触点可能形成死球，约占 20% 失败观察。横轴接触点法线近似水平，反射缺少向上分量，可能形成无法有效回到攻击区域的轨迹。此处需联合真实入射速度、接触法线、挡板速度及后续碰撞验证；不能仅凭角度把所有状态永久判死。80%/20% 同样属于待批量验证的初始假设。
- 几何语义继续遵循双投影模型：外环以真实碰撞点投影确定接触点和径向法线；内环以飞行角度投影到真实不规则曲线，并结合球半径与缺口直径投影判断实体接触/通行。生存域评估必须调用与真实碰撞一致的几何与反射模型，不另造一套不一致的简化物理。
- 新系统评估层级：①碰撞结果（出射方向/速度与误差）；②短期生存（后续 1–3 次碰撞、漏接风险与可恢复性）；③完整关卡通关（最终唯一主指标）。经过次数、轨迹密度或单次碰撞成功不能代替通关率。
- 生存域采用带样本量与置信度的统计估计。样本不足区域标为未知，不因少量成功直接列为安全区；条件成功状态必须保留速度、入射角、挡板速度等适用条件。高风险状态也先作为风险提示，不武断地永久屏蔽可能可救回的轨迹。
- 下一阶段施工方向：以第一关真实生产物理为基准，建立可重复、固定种子与跨种子验证的批量自动驾驶实验；分别扫描内环接球速度能力边界、外环横轴附近的死球风险边界；记录完整球轨迹、接触角/法线/入射与出射速度、挡板状态、失球原因和通关结果；由实验生成状态空间的可生存概率与可恢复性估计，再把可信生存域反馈给 RingPlanner / planAim。
- 验收原则：任何「完全体瞄准」策略都必须在相同初始条件下与稳定基准版本做完整第一关 A/B 对照，并在未见随机种子上验证泛化；只有真实通关率改善才保留。单元测试、碰撞矩阵、热图外观和局部预测精度均为中间证据，不可替代最终通关率。
- 本里程碑是设计理解与研究方向记录，不代表生存域概率已完成测量，也不代表完全体瞄准系统已经实现。当前不发布、不部署；手机实测仍留到开发侧验证充分之后。

### 2026-11-19 · 自动驾驶原型架构收敛 · 接球 / 甩球 / 生存域
- 用户明确将实现目标收敛为三个概念，不再堆叠独立驾驶规则：
  1. **接球（Catch）**：判断当前球状态能否被内环捕获，重点检查真实碰撞几何及捕手速度处理能力；内环实体壁全范围均可作为接球区域，不按角度建立黑名单。
  2. **甩球（Sling）**：球被捕获后执行真实物理甩球，把球送入有效攻击轨迹；甩球产生的初始速度必须处于下一次可接球能力范围内。速度控制与甩出角度控制仍遵循既定独立语义。
  3. **生存域（Viability Domain）**：判断当前状态及候选动作是否仍处于可持续生存、可恢复并有机会通关的状态集合。它为接球与甩球决策提供统一的风险判断，不另行增加互相冲突的启发式规则。
- 自动驾驶原型的数据流收敛为：读取真实球/挡板状态 → 生存域评估候选接触与后续状态 → 接球或甩球决策 → 真实物理执行 → 记录结果并更新评估数据。
- 用户提出的开发迭代原则：**原型 → 决策优化迭代**。先实现三个概念组成的最小完整闭环，确保能在真实第一关中持续运行；随后以真实通关率为唯一最终指标，逐步调整接球决策准确率。不要先构建复杂规则树或追求复杂热图。
- 关键优化指标是接球决策准确率：预测可接球却实际漏接属于假阳性；预测不可接球但实际可接住属于假阴性。两类错误都要记录，但权衡必须以最终通关率为准，避免为了降低漏接而错失可用接球机会。
- 生存域的输入仍需包含影响真实碰撞结果的必要状态（球位置/速度、内外壁投影接触几何、缺口净空、挡板位置/速度）；这些是物理状态，不意味着驾驶系统需要增加更多概念。
- 最新第一关基准实验仍只有 6 局：0/6 通关，中心/左/右挡板位置各 0/2；4 局运行至 90 秒超时，2 局触发重开。样本量远不足以估计真实通关率，但已足以说明当前 Auto 原型尚未达到通关目标。该数据作为诊断基线，不得包装成可靠胜率结论。
- 下一步实施顺序：①整理 Catch / Sling / Viability 三个清晰决策接口；②让 Auto 只通过这三个接口做完整驾驶，不叠加旁路策略；③用固定场景复现实验，逐项记录接球预测与真实结果；④再以跨种子完整第一关通关率调整接球阈值和甩球参数。
- 本记录是自动驾驶原型架构收敛，不代表完全体系统已经实现。所有概率与速度边界继续以实测验证；不发布、不部署 Pages，手机实测留待开发侧验收充分后。

# 第二章：统一物理引擎（全游戏基础设施重建）

> 本章是游戏所有物理对象的统一施工计划。它不是圆环捕手专属模块，也不是给现有反弹函数换名字。  
> 核心原则：**自然规律是规则，数学是语言，实验是裁判，代码是实现。**

## 2.1 重构目标与范围

建立适用于本游戏二维玩法的统一物理内核，统一处理：
- 球：质量、位置、线速度、加速度、动量、半径；未来若加入自转，再明确增加角速度与转动惯量。
- 挡板：运动学刚体，具有位置、速度、几何形状和接触表面速度；由游戏控制器驱动，驱动器做功必须可识别。
- 墙壁：静态刚体，位置固定、表面速度为零。
- 砖块：按游戏需求定义静态/可破坏刚体语义；碰撞响应与耐久度、破坏、得分分离。
- 圆环：运动学刚体及其内外壁曲线/缺口几何；内外壁材质参数属于接触材料配置，不另开物理旁路。

不预设必须引入大型第三方刚体引擎。先完成生产代码审计和最小二维物理内核设计，再用真实场景证明其正确性与性能。

## 2.2 统一架构边界（目标）

```
Game Rules       得分、砖块耐久、生命、关卡、技能与奖励
     ↑ 读取物理事件 / 提交控制请求
Physics World    统一世界状态、时间步与对象注册
     ↓
Broad Phase      候选接触对筛选
     ↓
Narrow Phase     精确几何接触：接触点、法线、穿透/间隙
     ↓
Contact Solver   相对速度、恢复、摩擦、冲量与约束求解
     ↓
Integrator       力/加速度积分、位置更新、连续碰撞/时间推进
     ↓
Telemetry        动量、能量、碰撞事件、数值异常与可复现实验记录
```

架构硬边界：
1. 物理引擎决定物体如何运动、如何接触、碰撞后速度如何变化。
2. 游戏规则决定碰撞后砖块扣血/消失、得分、生命变化、技能触发等。
3. 策略层不得直接改写球的位置或速度来伪造物理结果；必须通过力、冲量、运动学边界控制或明确标记的游戏效果接口。
4. 运动学挡板由程序驱动，不冒称封闭系统动量守恒；驱动器对球做功应能从接触表面速度和冲量计算。
5. 任何速度上限、保底速度、奖励加速、减速技能都必须标明是数值保护还是游戏规则，不得伪装成自然碰撞。
6. 单位、坐标方向、时间单位、质量单位和速度单位必须统一并写入接口契约。

## 2.6 重构风险与禁止事项

- 不允许一次性删除旧物理后再寻找替代方案。

- 不允许把样本很少的胜率报告成可靠概率。
